## Mac 验收顺序

1. 先运行 `swift test --package-path Core`。核心 package 不依赖 HealthKit，可在 Mac 本机执行。附带 app scheme 没有配置 app hosted tests；不要将一次无测试的 Cmd-U 当作已执行核心测试。
2. 运行 README 中的 `xcodebuild` 命令；然后在 Xcode 用自己的 Team 和 bundle ID 签名并安装到 Watch。
3. Debug `-demo` 检查首页及所有点击导航；移除参数重新启动，检查真实无数据状态。用 Release 确认即使传入 `-demo` 也不会产生演示结果。
4. 对照以下场景完成真机测试，记录所用 Watch 型号、watchOS 与 Xcode 版本；不要把某一台设备通过视为所有设备通过。

| 场景 | 期望 |
|---|---|
| 首次运行 | 欢迎页可直接在手表填写并授权；没有 iPhone app 登录步骤 |
| 全拒绝/部分授权 | 不说“已授权所有数据”；缺失项不记零，不生成虚假年龄 |
| 心率可读但无 VO₂max | 指标仍可展示；年龄显示 0/3 等实际采样日进度 |
| 1 天有多条 VO₂max | 只算 1 个采样日，不绕过 3 天门槛 |
| 样本超过 14 天 | 当前参考年龄停止展示 |
| 年龄 19/80，未选常模或暂停换算 | 不输出年龄，健康记录仍可查看 |
| 个人基线不足 | 显示日数与“基线待积累”，不报变化百分比或精度 |
| 睡眠跨午夜、awake、重叠父/子记录 | 不重复累加，不计清醒；已完成 noon 窗口才纳入 |
| 夏令时或切换时区 | Calendar 日边界有效；历史分组可能随当前时区变化 |
| 两块手表/重复运动时段 | 相同时间段不会双计；与系统圆环的差异按文档解释 |
| HealthKit 被锁定/超时/记录上限 | 该指标显示读取问题，不使用上一轮陈旧快照冒充新结果 |
| 授权撤销或系统样本删除后刷新 | 重新查询，不恢复旧健康磁盘缓存 |
| 退后台再进前台 | 重新查询；无持续 workout、无后台常驻采样 |
| 开启飞行模式 | 不需要服务器；能显示设备当前可读取的数据 |
| 重启 App | 个人设置保留，健康记录重新读取 |
| 清除本地设置 | 返回欢迎页；系统健康记录不被删除 |

## UI 验收

- 小尺寸及大尺寸 Apple Watch 各检查一次；概览年龄、不可估算文案、指标卡、Picker、方法长文均能滚动且不截断重要信息。
- 检查系统最大辅助字体；大数字有独立 VoiceOver 标签，其他主要信息使用系统动态字体。
- VoiceOver 能读出参考年龄的限定语、真实数值/单位、采样日数与按钮作用。曲线作辅助视觉，详情列表提供相同数据。
- 缺测曲线不跨缺失日连线，不以填零产生假波动；颜色只是区分指标，不是唯一的状态表达。
- 演示模式顶部标识持续可见；常亮/后台隐私行为在真机验证。
- 叠层光晕、星点是装饰，不显示没有定义的“健康完成度”。高于/低于常模端点有明确符号及说明。

## 2.0 UI 回归验收

- 点击首页年龄进入依据页；“估算波动”“读懂年龄”“数据状态”分别打开独立页，系统返回有效。
- 37 岁对比实际 42 岁显示 `-5 岁`；43 对比 40 显示 `+3 岁`；显示年龄相同为 `0 岁`，无 `-0`。
- 差值与已显示的整数年龄保持一致；常模端点显示“已到参考边界”，不生成精确差值。新增 4 个 Swift 测试方法，总计 24 个，仍须在 Mac 执行。
- 六个健康入口分别可点击；VO₂max 即使不满足年龄换算条件仍可显示已读取的值，并标明采样日与最近日期。
- 单项详情 → 每日记录 / 怎么看；详情从当前 AppModel 重新派生，退后台重新进入或刷新后不保留路由中的旧健康快照。
- 首次引导分步推进；在适用范围页面返回后已填写的资料不丢失；清除设置后回到欢迎页而非停留在失效的导航页。
- 开启“减少动态效果”后无入场旋转、缩放和数字转场动画；按压仍有透明度反馈。无永续动画或定时刷新。
- 辅助大字体时指标网格为单列。最小 Watch 尺寸下年龄差位于年龄下方且可见/可滚动到达，按钮不小于 44 pt 高。
- 已完成源码和工程静态一致性检查，未进行模拟器截图或真机动态视觉验证。
