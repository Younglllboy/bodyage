# 方法说明与证据边界

检索日期：2026-10-07。本文区分发表结果、应用的工程假设和未来需要完成的验证。本原型的年龄值不是诊断或已验证的生物衰老时钟。

## 1. 为什么没有把五种指标加权成“身体年龄”

年龄预测、健康风险预测、生物衰老测量是不同的目标。睡眠、运动、心率与年龄/健康的统计关联，不会自动产生可用于个人的“加减岁数”系数。还存在运动与 VO₂max、睡眠与 HRV 等相关性；任意加权会重复计算同一因素。相关系数和风险比也不能直接换算成年龄。

Miller 等 2025 年的 PpgAge 研究是值得参考的方向，但它使用研究采集的原始多通道 PPG 波形、学习到的表示及训练模型。研究库公开的是未训练模型与训练/分析流程，原始研究数据受限。其性能不能移植给普通 HealthKit 的心率、睡眠等汇总字段。当前源码既没有这些波形输入，也没有经验证的训练权重，因此不声称复现 PpgAge。[研究原文](https://www.nature.com/articles/s41467-025-64275-4)，DOI: 10.1038/s41467-025-64275-4。

因此，本应用使用一个范围明确、可审查的“心肺体能对应年龄”，同时展示其他指标和个人基线。它是健康概览中的参考坐标，不是五种数据共同验证出的全身年龄。

## 2. 年龄换算的唯一依据

Kaminsky、Arena、Myers 的 FRIEND 2015 研究收集美国 7,783 次成人跑台心肺运动测试，发表性别和年龄段的 VO₂max 常模。使用其 **表 3、第 50 百分位**，不是表 4 的均值，也没有混入 Cooper Clinic 的数据。

| 年龄段 | 男性 P50 | 女性 P50 | 本实现的年龄中点 |
|---|---:|---:|---:|
| 20–29 | 48.0 | 37.6 | 24.5 |
| 30–39 | 42.4 | 30.2 | 34.5 |
| 40–49 | 37.8 | 26.7 | 44.5 |
| 50–59 | 32.6 | 23.4 | 54.5 |
| 60–69 | 28.2 | 20.0 | 64.5 |
| 70–79 | 24.4 | 18.3 | 74.5 |

VO₂max 单位为 mL·kg⁻¹·min⁻¹。来源：[全文及表 3](https://pmc.ncbi.nlm.nih.gov/articles/PMC4919021/#T3)，DOI: 10.1016/j.mayocp.2015.07.026。

**新增的工程假设**：把每个十岁组的参考值放在组中点，连接相邻节点，再逆向线性插值。论文没有验证这条逆向插值为个人生物年龄。美国无已知特定心肺疾病的参考群体不等于全球人群；跑台直接测量不等于手表估计；横断面组间差异也不是个人纵向衰老速度。选择这张公开表是为了可复核，不能称为所有人群的最新最佳常模。

设同组的两个相邻 VO₂max 中位数为 `v_i ≥ x ≥ v_(i+1)`，年龄节点为 `a_i`、`a_(i+1)`：

```text
x = median(每个采样日的 VO₂max 中位数)
参考年龄 = a_i + (v_i - x) / (v_i - v_(i+1)) × (a_(i+1) - a_i)
```

例如男性参考组，`x = 40.1` 位于 `42.4` 和 `37.8` 的中点，结果为 `39.5`，界面四舍五入显示约 **40 岁**。实际年龄只用于适用性筛选和差值说明，不加回公式，不以此“校正”结果。显示整数只是避免多余小数，不表示有 ±1 岁准确度。

若 x 高于最年轻节点，内部保留 24.5 的删失边界，UI 显示 `≤25`；若低于最年长节点，保留 74.5，显示 `≥75`。这些是取整后的参考端点标签，不是对真实身体年龄的不等式判断。端点不计算“年轻/年长几岁”，不外推儿童或 80 岁以上常模。

## 3. 手表测量误差和不确定性

Apple 的官方说明介绍了 VO₂max 的估计条件、支持范围和影响因素。它通常依赖符合条件的户外步行/跑步/徒步，也受个人资料和药物等影响。该值是估计，不能当作气体代谢仪直接测量。[Apple 心肺体能说明](https://support.apple.com/en-us/108790)、[Apple 技术白皮书](https://www.apple.com/healthcare/docs/site/Using_Apple_Watch_to_Estimate_Cardio_Fitness_with_VO2_max.pdf)。白皮书的验证对应其当时设备与算法，并不自动覆盖后续全部系统版本。

独立验证也提示个体误差不可忽略，例如 Lambe 等 2025 年的验证研究。不能看到一个研究的群体平均偏差，就给所有用户统一加一个常数；研究人群、体能分布、设备及软件版本不同，偏差未必可迁移。[原文](https://pmc.ncbi.nlm.nih.gov/articles/PMC12080799/)，DOI: 10.1371/journal.pone.0323741。

本应用没有足够的数据建立经过校准的年龄预测区间，因此**不显示“95% 置信区间”或“准确率 90%”**。替代的是明确标注的敏感性实验：分别计算 `x + 3.5` 和 `x - 3.5` 的参考年龄。3.5 对应常用的 1 MET 尺度；这是人为选择的扰动大小，不是个人误差界限。实际误差和人群迁移误差可能更大，不能把显示范围当作真实年龄很可能所在的区间。

多日中位数可减少异常值和密集采样日的影响，但不能消除系统性偏差。把常模函数倒过来，也不等于统计意义的 `E[年龄 | VO₂max]`，更不是疾病风险等效年龄。

## 4. 其他指标如何参与综合分析

这里的“综合”是同屏查看状态、近期值、个人历史差异与数据质量；没有冒充已训练的多变量年龄模型。应用不根据简单联合升降规则诊断感染、压力过高或过度训练。

| 指标 | 提供的信息 | 不做的推断 |
|---|---|---|
| 静息心率 | 系统日级静息心率的变化 | 心率低必定健康或年轻 |
| HRV SDNN | 同人、同设备下的探索性趋势 | 与 RMSSD 直接比较，或越高越好 |
| 呼吸频率 | 实际采样时段的频率及变化 | 全天呼吸状况、肺功能或睡眠呼吸暂停诊断 |
| 睡眠 | 已记录 asleep 时长 | 用深睡百分比推算大脑年龄 |
| 运动分钟 | 记录到的运动情况 | Apple Exercise Time 精确等于 WHO 中高强度运动剂量 |

成年人规律睡眠至少 7 小时的提示来自 AASM/SRS 共识，不设置“睡得更多就扣岁数”，也不把 >9 小时一概作为有害。[共识原文](https://pmc.ncbi.nlm.nih.gov/articles/PMC4434546/)，DOI: 10.5664/jcsm.4758。

WHO 对成人运动建议区分中等和高强度活动，不能由一个未经强度分类的手表分钟总量直接判定是否达标。若扩展运动建议，应另外处理强度、力量训练和适用人群。[WHO 2020 指南](https://www.who.int/publications/i/item/9789240015128)。

## 5. 聚合、缺失与工程阈值

1. 数据源：Apple 系统来源 + Watch 产品/设备元数据；剔除手填。仅凭来源名称字符串像“Watch”不够，因此还检查系统 bundle 前缀。缺失元数据的记录保守排除。这是工程来源规则，需随系统版本回归验证。
2. 原始数量数据：剔除 NaN/Infinity、非法时间和未来样本；UUID 去重。同日取中位数，再跨日取中位数，避免一天频繁记录主导整个窗口。数值为 0 的生理数量不参与日中位数；运动中显式记录的 0 可保留。
3. 睡眠：只取 asleepUnspecified/Core/Deep/REM。重叠区间取并集，不累加父级与子阶段，排除 inBed、awake。按本地中午至下一中午归组，合并夜间与白天睡眠。该日界适合一般夜间睡眠者，对跨中午的轮班睡眠可能分割，应解释而非称其“差睡眠”。
4. 运动：以原记录分钟/区间长度作为速率，在重叠时段取最高速率，上限为每现实分钟 1 运动分钟，再按本地完整日期积分。这避免重复累计，代价是隐含均匀分布并可能低估真正互补的记录。结果命名为“已记录运动分钟”，不是精确运动环复刻。零长度记录不使用。
5. 所有日边界使用 Calendar 加减日，避免把夏令时日期强行设为 86,400 秒。时区采用当前设备时区，旅行切换后历史日归组可能变化，本版本不保存每条样本原时区。
6. 缺失不记零；区分没有结果、记录过期、读取错误。HealthKit 不暴露逐项读权限是否被拒绝，因此空数据不能标成“用户拒绝”。[Apple 授权文档](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)。
7. 年龄的 3 个采样日/14 天新鲜度；趋势的 3/7 近期采样日、7/21 基线日、3 天新鲜度，均是**本应用工程门槛**，不是论文验证出来的准确率保证。数据再多，也不会让输出自动成为全身生物年龄。
8. 不假设手表具有手机 Health 数据库的全部历史，不用服务器或手机回填。可读取历史不够时就不比较基线。每次重新查询，而非长期保存可能已被用户撤销或删除的健康样本。

## 6. 若将来要做真正的多指标模型

这部分是研究计划，**不在当前代码中伪装成已完成的模型**。

- 先定义目标：健康常模对应年龄、风险等效年龄或生物衰老速度，不能混称。要有明确的目标人群及临床排除标准。
- 在合规取得同意的真实队列中采集可获得的传感器特征、设备/系统版本、佩戴缺失、年龄与相关协变量；如果研究生物老化，还需独立功能、疾病结局或其他有效外部参照，不能只用日历年龄训练后宣布测到生物年龄。
- 以受试者为单位划分训练、验证、测试集；做独立地区/设备外部验证和时间外推，避免同人不同夜晚泄漏到测试集。个人基线不能使用未来数据。
- 比较简单基线模型与多变量模型，处理特征相关、缺失非随机、年龄回归均值偏差和校准；预注册主要结局。使用真实留出集报告误差、校准、区间覆盖和人群子组结果。
- 验证超出实际年龄等标准因素后，年龄差是否仍有独立的结局或功能预测意义；测量重复性和对纵向变化的解释也需检验，不能把短期生理波动称作逆转衰老。
- 发布模型卡、版本、输入要求、外推边界和失效条件；部署时保留当前“无法估算”机制，再通过 watchOS Core ML 等方式进行本地推断。

## 7. 设计资料不作为科学证据

[BodyCharge 商店页面](https://apps.apple.com/us/app/bodycharge-health-monitor/id6738761582)用于了解类似产品如何组织健康概览。它的评分或营销描述不作为本应用换算公式的证据；界面和素材没有复制。
